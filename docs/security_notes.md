# Tata AI Legal Intelligence System - Security & Governance Notes

## 🛡️ 1. API Key & Secrets Governance

### PostgreSQL Dynamic Key Persistence
To eliminate security vulnerabilities associated with plain-text configuration files and survive Render's ephemeral container wipes, active API keys are managed dynamically:
* Keys saved via the UI are committed directly to the `system_config` table in PostgreSQL.
* The backend reads from PostgreSQL first, completely overriding static container environment variables (`os.getenv("GEMINI_API_KEY")`).

### Key Masking & Information Disclosure
* API keys are **never returned in full** to the frontend or included in client-side logs.
* Keys are securely masked on retrieval using `mask_key_suffix()` (e.g., returning only `...fkkQ` or `...pLeg`).

---

## 🔒 2. Data Protection & Sanitization

### Input & Text Sanitization
* All incoming string parameters (usernames, filenames, extracted text, risk rationales) are processed through `sanitize_text()` to strip NUL bytes (`\x00`). This prevents PostgreSQL string truncation crashes and SQL injection vectors.

### JSON Serialization Security
* Mathematical `NaN` and `Infinity` float values generated by failed or timed-out AI evaluations are sanitized using `sanitize_score()` prior to serialization. This prevents FastAPI response serialization panics.

---

## 👥 3. Role-Based Access Control (RBAC)

* **Admin Role:** Full administrative privileges, including dynamic Gemini API key rotation, system model selection, and global audit archive inspection.
* **Compliance Specialist / User Role:** Access restricted strictly to contracts uploaded by their registered email address (`uploaded_by == current_user.email`).

---

## ⚡ 4. Free-Tier Resilience & Rate-Limit Safeguards

To ensure system stability under Google Free-Tier quota constraints:
* **`RateLimitedLLM` Wrapper:** Catches HTTP 429 (`RESOURCE_EXHAUSTED`) errors and applies exponential backoffs.
* **Isolated Event Loops:** Evaluators run on isolated `asyncio` loops within background worker threads to avoid interfering with FastAPI's `uvloop` architecture.
* **Strict Evaluation Timeouts:** Evaluators use `RunConfig(timeout=180, max_workers=1)` to handle slow API responses gracefully without crashing active user sessions.

---

## 📜 5. Immutable Audit Trail

* Every accept or reject action taken by a human compliance officer is recorded in the `audit_logs` table.
* Logs store the user's authenticated email, timestamp, exact action, and reviewer notes, providing a non-repudiable audit history.
